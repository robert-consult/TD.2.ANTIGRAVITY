## 3) Must-fix patches (inline)

### 3.1 Prevent admin endpoints during impersonation (critical)

#### Patch `server/middleware/adminGuard.ts`

```ts
import { Request, Response, NextFunction } from "express";

export function adminGuard(req: Request, res: Response, next: NextFunction) {
  // Critical: do not allow admin routes while impersonating
  if (!req.user || req.user.role !== "admin" || req.user.impersonated === true) {
    return res.status(403).json({ error: "Admin access required" });
  }
  next();
}
```

#### Patch `server/routes/admin.ts` view-as token role handling

In `POST /admin/view-as/start`, set an effective role that cannot elevate:

```ts
const effectiveRole = u.role === "admin" ? "user" : u.role;

const token = jwt.sign(
  {
    id: u.id,
    role: effectiveRole,
    username: u.username,
    email: u.email,
    impersonated: true,
    impersonated_by: req.user!.id,
    impersonated_original_role: u.role
  },
  process.env.JWT_SECRET!,
  { expiresIn: "15m" }
);
```

This prevents “admin-as-admin” impersonation from accidentally having admin privileges.

### 3.2 CSV injection mitigation (critical)

Patch `server/utils/csv.ts`:

```ts
export type CsvHeader = { key: string; label: string };

function preventCsvFormulaInjection(s: string): string {
  // Excel/Sheets formula injection protection
  // If begins with = + - @, prefix with apostrophe
  return /^[=+\-@]/.test(s) ? `'${s}` : s;
}

function escapeCsvValue(v: unknown): string {
  if (v === null || v === undefined) return "";
  let s = typeof v === "string" ? v : JSON.stringify(v);

  s = preventCsvFormulaInjection(s);

  const mustWrap = /[",\n\r]/.test(s);
  const escaped = s.replace(/"/g, '""');
  return mustWrap ? `"${escaped}"` : escaped;
}

export function toCsv(headers: CsvHeader[], rows: Record<string, any>[]): string {
  const headLine = headers.map(h => escapeCsvValue(h.label)).join(",");
  const lines = rows.map(r => headers.map(h => escapeCsvValue(r[h.key])).join(","));
  return [headLine, ...lines].join("\n") + "\n";
}

export function sendCsv(res: any, filename: string, csv: string) {
  res.setHeader("Content-Type", "text/csv; charset=utf-8");
  res.setHeader("Content-Disposition", `attachment; filename="${filename}"`);
  res.status(200).send(csv);
}
```

### 3.3 Clamp `since_days` and parameterize intervals (recommended)

Where you currently do:

```sql
entry_time >= NOW() - INTERVAL '${sinceDays} days'
```

Replace with parameter-safe form:

#### Example patch pattern (Postgres):

```sql
AND ($2::int = 0 OR entry_time >= NOW() - make_interval(days => $2::int))
```

In TypeScript:

```ts
const sinceDaysRaw = req.query.since_days ? Number(req.query.since_days) : 30;
const sinceDays = [0, 7, 30, 90].includes(sinceDaysRaw) ? sinceDaysRaw : 30;
```

Apply this pattern to:

* `computeInsights`
* admin snapshot totals query
* `getUserSessions` queries

This upgrades you from “likely safe” to “institutionally clean.”

### 3.4 Audit privileged exports during View-As (high-value compliance improvement)

In `server/routes/exports.ts`, if the request is impersonated, log it:

```ts
import db from "../db";

async function logViewAsExport(req: any, actionType: string, metadata: any) {
  if (req.user?.impersonated && req.user?.impersonated_by) {
    await db.query(
      `INSERT INTO admin_actions (admin_id, user_id, action_type, metadata, ip, user_agent)
       VALUES ($1,$2,$3,$4,$5,$6)`,
      [
        req.user.impersonated_by,
        req.user.id,
        actionType,
        JSON.stringify(metadata || {}),
        req.ip || null,
        req.headers?.["user-agent"] || null
      ]
    );
  }
}
```

Then call it inside export handlers, e.g.:

```ts
await logViewAsExport(req, "VIEW_AS_EXPORT_JOURNAL_CSV", { endpoint: "/journal/export.csv" });
```

This is one of the easiest “allocator confidence” wins.

* Your session integration is schema-tolerant but intentionally “probing.” For production:
