1) Research Findings (Implementation Best Practices)
A. Deactivation vs. Deletion (Soft Delete) patterns
Industry-standard approach is:

“Deactivate” = immediate disablement for user access; data retained for operations/audit.

“Delete” = user intent for permanence; however many platforms still retain data for compliance/audit/financial records and treat it as a soft delete (account disabled + data retained + limited re-identification controls depending on policy).

Key reasons:

Auditability: financial/trading applications often require immutable audit trails, operational logs, and retention for fraud investigations.

Compliance: GDPR/CCPA allow retention where required for legal obligation or legitimate interests (e.g., fraud prevention, financial record retention), but you should disclose this clearly in UX.

B. Session Revocation / Immediate Logout
Best practices from OWASP-style session management guidance:

Account status change (disable/delete) must:

Revoke all active sessions server-side

Destroy current session

Invalidate session identifiers so any stale cookies stop working

Defensive checks should also be added to auth middleware so even if a stale session cookie exists, requests fail if the user is disabled/deleted.

C. Blocking Future Logins/Signups for the Email
Common approach:

Keep the email on the user record with a unique constraint so signups cannot reuse it.

Ensure login checks isDisabled/isDeleted and blocks authentication.

If you later anonymize email for other lifecycle workflows (like inactivity cleanup), that would allow re-registration; your requirement explicitly forbids that for self-service deactivate/delete, so do not anonymize email in these flows.

D. Public/Trader-facing Visibility
Best practices:

Any public endpoints (leaderboards, public profiles) must filter out disabled/deleted accounts.

Avoid relying only on UI; enforce in backend queries and/or storage layer.

function baseLocale(value?: string | null): string {
  return String(value || "").trim().toLowerCase().split("-")[0] || "";
}

function applyStoredLocale(user: User | null): User | null {
  if (!user || typeof window === "undefined") return user;
  try {
    const stored = localStorage.getItem("i18n.locale");
    if (!stored) return user;
    const storedBase = baseLocale(stored);
    const userBase = baseLocale(user.language);
    if (!userBase || (userBase === "en" && storedBase && storedBase !== "en")) {
      return { ...user, language: stored };
    }
  } catch {
    // ignore storage failures
  }
  return user;
}

function formatCompactNumber(value: number): string {
  const absValue = Math.abs(value);
  if (absValue >= 1_000_000_000) {
    return (value / 1_000_000_000).toFixed(1).replace(/\.0$/, '') + 'B';
  }
  if (absValue >= 1_000_000) {
    return (value / 1_000_000).toFixed(1).replace(/\.0$/, '') + 'M';
  }
  if (absValue >= 1_000) {
    return (value / 1_000).toFixed(1).replace(/\.0$/, '') + 'K';
  }
  return value.toLocaleString();
}

function baseLocale(value?: string | null): string {

function applyStoredLocale(user: User | null): User | null {
  if (!user || typeof window === "undefined") return user;
  try {
    const stored = localStorage.getItem("i18n.locale");
    if (!stored) return user;
    const storedBase = baseLocale(stored);
    const userBase = baseLocale(user.language);
    if (!userBase || (userBase === "en" && storedBase && storedBase !== "en")) {
      return { ...user, language: stored };
    }
  } catch {
    // ignore storage failures
  }
  return user;
}

  const absValue = Math.abs(value);
