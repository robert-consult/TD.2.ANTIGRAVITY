# A) Fix 1 — Session Revocation Enforcement + Session Heartbeat (Last Active)

## Root Cause

Your app has **two auth patterns**:

* Many routes only check `req.session.userId` (via `ensureAuth`)
* Session revocation and lastActiveAt heartbeat logic exists elsewhere but is not enforced globally

Result:

* **Revoked sessions may continue to function** because most routes do not check `user_sessions.revoked_at`
* `last_active_at` often becomes stale, causing “static session cards” and unreliable session UX

## Solution

Add a global middleware that runs for **all `/api` calls**:

* If session is revoked → destroy session and return 401
* Otherwise → update lastActiveAt (`touchSession`) so UI “Last active” is real

### 1) Add File: `server/middleware/sessionValidity.ts`

Copy/paste the full file:

```ts
import type { Request, Response, NextFunction } from "express";
import { and, eq } from "drizzle-orm";
import { db } from "@db";
import { userSessions } from "@shared/schema";
import { touchSession } from "../security/sessionTrail";

function destroySession(req: Request): void {
  try {
    (req.session as any)?.destroy?.(() => {});
  } catch {
    // ignore
  }
}

function sessionIdFromReq(req: Request): string | null {
  const sid = (req as any).sessionID;
  return typeof sid === "string" && sid.length > 0 ? sid : null;
}

/**
 * Middleware to:
 * 1) Reject requests for revoked sessions (401)
 * 2) Update lastActiveAt (heartbeat) on every authenticated request
 */
export async function sessionValidityGuard(req: Request, res: Response, next: NextFunction) {
  const userId = (req.session as any)?.userId;
  const sessionId = sessionIdFromReq(req);

  if (!userId || !sessionId) return next();

  try {
    const row = await db
      .select({ revokedAt: userSessions.revokedAt })
      .from(userSessions)
      .where(and(eq(userSessions.userId, Number(userId)), eq(userSessions.sessionId, sessionId)))
      .get();

    if (row?.revokedAt) {
      destroySession(req);
      return res.status(401).json({ message: "Session revoked" });
    }

    // Best-effort heartbeat; never block request flow.
    touchSession(sessionId);
  } catch (e) {
    console.error("[sessionValidityGuard] error", e);
  }

  return next();
}
```

### 2) Patch: `server/routes.ts`

Add the import near the other middleware imports:

```ts

```

Then register it **immediately after** `impersonationGuard`:

```ts
app.use("/api", impersonationGuard);

// Session revocation enforcement + lastActiveAt heartbeat.
// Required for: "logout other devices" and accurate "Last active" values.
app.use("/api", sessionValidityGuard);
```

**Outcome**

* “Terminate session / terminate other sessions” actually takes effect immediately
* “Last active” updates on every authenticated call
* Revoked sessions are refused across the entire API surface

# B) Fix 2 — “Invalid Date” + Login History Data Mismatch

## Root Cause

There is inconsistent timestamp shape across APIs:

* Some routes return `Date` objects serialized as ISO strings
* Some return unix seconds
* UI sometimes multiplies by `1000` assuming seconds

That creates `NaN` date math → “Invalid Date”.

## Quick Frontend Fix (safe parsing everywhere)

In `client/src/pages/ProfileSettings.tsx`, replace the current `safeFmt` with this robust version:

```ts
const safeFmt = (ts: unknown) => {
  if (ts === null || ts === undefined) return "Unknown";

  // Date object
  if (ts instanceof Date) return ts.toLocaleString();

  // numeric seconds/ms
  if (typeof ts === "number") {
    const ms = ts < 1e12 ? ts * 1000 : ts; // heuristic: < 1e12 => seconds
    const d = new Date(ms);
    return isNaN(d.getTime()) ? "Unknown" : d.toLocaleString();
  }

  // ISO string or numeric string
  if (typeof ts === "string") {
    const numeric = Number(ts);
    if (!Number.isNaN(numeric)) {
      const ms = numeric < 1e12 ? numeric * 1000 : numeric;
      const d = new Date(ms);
      return isNaN(d.getTime()) ? "Unknown" : d.toLocaleString();
    }
    const parsed = Date.parse(ts);
    if (!Number.isNaN(parsed)) return new Date(parsed).toLocaleString();
  }

  return "Unknown";
};
```

# C) Fix 3 — Timezones must be UTC/GMT standard format (plus “deep city-based”)

Your repo already generates deep city-based timezone labels from tzdb; however the offset prefix must be **explicit UTC/GMT**.

## Patch: `server/utils/tzOffset.ts`

Replace `fmtUtcOffset` with:

```ts
export function fmtUtcOffset(mins: number): string {
  const sign = mins >= 0 ? "+" : "-";
  const abs = Math.abs(mins);
  const hh = String(Math.floor(abs / 60)).padStart(2, "0");
  const mm = String(abs % 60).padStart(2, "0");
  return `UTC${sign}${hh}:${mm} (GMT${sign}${hh}:${mm})`;
}
```
