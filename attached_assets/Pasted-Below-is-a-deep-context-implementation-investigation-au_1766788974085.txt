# 0) Audit Objective and Evidence Standard

## Objective

Detect and surface:

1. **Multi-account usage** on same device/network (shared device, shared IP clusters)
2. **Account delegation / account sharing** (rapid churn of IP/UA/device/geo, concurrent sessions)
3. **Two-account hedging to beat odds** (BUY vs SELL in same symbol across accounts with same device/IP within time window)

## Evidence required for each checklist item

* **File path + code excerpt** (or function name + line range)
* **DB proof**: select query showing rows created/updated as expected
* **UI proof**: screenshot or screen recording + network calls (DevTools) showing endpoints hit
* **Negative test**: confirm false positives are controlled (dedupe, thresholding)

# 3) Data Capture Points (Wiring into the App)

This is the most common failure category. Agent must trace: **request → middleware → engine hook → DB rows**.

## 3.1 Auth / req.user presence

Verify:

* `req.user.id` exists for all authenticated calls to `/api/grift/ping`
* login sets session cookie and server attaches req.user

**Fail pattern**

* Ping endpoint returns 401 always; concurrency detection never triggers.

## 3.2 Device ID capture

Verify:

* Client sets `X-Device-Id` header (or equivalent)
* Server reads `x-device-id` case-insensitive

**Pass criteria**

* Observations contain non-null `device_id` for logged-in sessions.

**DB check**

```sql
SELECT COUNT(*) withDevice, COUNT(*) total
FROM grift_observations
WHERE device_id IS NOT NULL;
```

## 3.3 IP capture

Verify precedence order:

* `CF-Connecting-IP` → `X-Forwarded-For` → `X-Real-IP` → socket addr

**Pass criteria**

* `ip` not constantly null in production hosting.

## 3.4 ASN / Org capture

Verify:

* Works with your deployment provider headers (Cloudflare or Vercel)
* Acceptable null behavior when unavailable

**DB checks**

```sql
SELECT COUNT(*) total, SUM(CASE WHEN asn IS NOT NULL THEN 1 ELSE 0 END) withAsn
FROM grift_observations;
```

## 3.5 Geo capture

Verify:

* Country from headers; coordinates optionally from client ping body
* Coordinates not mandatory (geo velocity only runs with lat/lon present)

**DB checks**

```sql
SELECT COUNT(*) total,
       SUM(CASE WHEN country IS NOT NULL THEN 1 ELSE 0 END) withCountry,
       SUM(CASE WHEN latitude IS NOT NULL AND longitude IS NOT NULL THEN 1 ELSE 0 END) withCoords
FROM grift_observations;
```

### 4.1.1 Dedupe key validation

```sql
FROM grift_signals
ORDER BY updated_at DESC
```

## 4.2 Multi-account on same device detection

Test scenario:

* Create User A and User B
* Log in A from device D
* Log out
* Log in B from same device D

Expected:

* `grift_device_users` shows device mapped to 2 users
* `grift_signals` has `MULTI_ACCOUNT_DEVICE` with `primary_user_id` and `secondary_user_id`

**DB checks**

```sql
SELECT * FROM grift_device_users WHERE device_id = '<device>';
SELECT * FROM grift_signals WHERE rule_code='MULTI_ACCOUNT_DEVICE' ORDER BY created_at DESC;
```

## 4.3 Hedge-pair detection (two-account hedge)

Test scenario:

* A opens BUY on XAUUSD
* B opens SELL on XAUUSD within hedge window
* same deviceId (or same IP if allowIpMatch enabled)

Expected:

* `grift_trade_observations` has both trades
* `grift_signals` has `HEDGE_PAIR` with symbol, trade_id, both user ids

**DB checks**

```sql
SELECT * FROM grift_trade_observations WHERE symbol='XAUUSD' ORDER BY ts DESC;
SELECT * FROM grift_signals WHERE rule_code='HEDGE_PAIR' ORDER BY created_at DESC;
```

## 4.4 Churn detection (IP/UA/Device/ASN)

Test scenario:

* For the same user within churn window:

  * vary IP (use VPN/proxy or simulate by header override in dev)
  * vary UA (change browser/UA header)
  * vary deviceId (clear localstorage / new device)
  * vary ASN (harder to test; simulate header in dev)

Expected:

* `IP_CHURN`, `UA_CHURN`, `DEVICE_CHURN`, `ASN_VOLATILITY` signals appear
* Evidence includes the unique set counts and recent observation sample

**DB check**

```sql
SELECT rule_code, points, evidence_json
FROM grift_signals
WHERE primary_user_id=<id> AND rule_code IN ('IP_CHURN','UA_CHURN','DEVICE_CHURN','ASN_VOLATILITY')
ORDER BY created_at DESC;
```

## 4.5 Geo velocity detection

Test scenario:

* Send ping with coords in one city

Expected:

* `GEO_VELOCITY` generated with distance/velocity in evidence

**DB check**

```sql
SELECT * FROM grift_signals WHERE rule_code='GEO_VELOCITY' ORDER BY created_at DESC;
```

## 4.6 Concurrent sessions detection

Test scenario:

* Same user logged in on device1 and device2 concurrently
