## 0) “Non-Negotiables” (acceptance criteria)

Agent 3 should treat these as **release-blocking**:

1. **Email enforcement is deterministic** (no drift):

   * **Grace**: unverified users can trade for 14 days from signup.
   * **Lock**: after day 14, exposure-increasing actions are blocked until verified.
   * **Re-verify**: after verification, rolling 30-day re-verification required; overdue eventually locks.
   * **Single source of truth**: `resolveAccountState()` in `shared/policyDecision.ts` controls UI + API gating.

2. **SMS is never required at signup**:

   * Only unlocked when contender criteria are met and email is currently in good standing.

3. **All state changes are auditable**:

   * Every verification / lock / unlock / OTP / KYC event emits a hash-chained record in `identity_audit`.

4. **Profile Settings actually surfaces real trails**:

   * “Recent Login Activity” pulls from the login trail tables (not dummy data).
   * “Active Sessions” lists sessions and supports terminating other devices.

5. **Timezones are shown in UTC/GMT standard format**:

   * Display format: `(UTC±HH:MM) Region/City · city1, city2…` (not raw `-11:00 …`).
   * Country list is canonical and searchable.

6. **Full trader-facing UI is multilingual**:

   * Entire trader UX (buttons, labels, toasts, validation messages, email/SMS templates) switches language based on selected preference.

## 6) Concrete bug: “Invalid Date” and missing login history (must fix)

Your screenshot (“Last active: Invalid Date”) is consistent with a real mismatch in the current repo:

* Backend `/api/profile/login-history` returns objects with **`eventAt`** (Date/ISO).
* UI renders **`login.createdAt * 1000`**, which will be `undefined * 1000` → invalid date.

### Patch (client): fix login history rendering

**File:** `client/src/pages/ProfileSettings.tsx`
Replace the login history timestamp logic with robust parsing:

```tsx
// Replace any usage like: new Date(login.createdAt * 1000)
// with:

function parseAnyDate(v: any): Date | null {
  if (!v) return null;
  if (v instanceof Date) return isNaN(v.getTime()) ? null : v;
  if (typeof v === "number") {
    const ms = v > 0 && v < 1e12 ? v * 1000 : v;
    const d = new Date(ms);
    return isNaN(d.getTime()) ? null : d;
  }
  if (typeof v === "string") {
    const d = new Date(v);
    return isNaN(d.getTime()) ? null : d;
  }
  return null;
}

// In render:
const at = parseAnyDate((login as any).eventAt ?? (login as any).createdAt ?? (login as any).at);
const atLabel = at ? at.toLocaleString() : "Unknown";
```

### Patch (server alternative): normalize login history response

**File:** `server/routes.ts` `/api/profile/login-history`

```ts
app.get("/api/profile/login-history", ensureAuth, async (req, res) => {
  const rows = await getRecentLoginActivity(req.session.userId!, 10);
  res.json(rows.map(r => ({
    ...r,
    // normalize to ms epoch for UI simplicity
```

## 8) Resend integration (required) — minimal production-grade drop-in

**File:** `server/routes/verification.ts` (replace console-stub)

1. Install:

```bash
npm i resend
```

2. Add env:

* `RESEND_API_KEY`
* `RESEND_FROM` (e.g. `no-reply@yourdomain.com`)
* `APP_BASE_URL` (e.g. `https://yourapp.com`)

3. Replace `sendVerificationEmail()`:

```ts
import { Resend } from "resend";

const resend = new Resend(process.env.RESEND_API_KEY || "");

async function sendVerificationEmail(email: string, token: string, opts?: { language?: string }) {
  const baseUrl = process.env.APP_BASE_URL || "http://localhost:5000";
  const from = process.env.RESEND_FROM || "no-reply@example.com";
  const link = `${baseUrl}/verify-email?token=${encodeURIComponent(token)}`;

  // Minimal localization hook (wire into full i18n later)
  const lang = (opts?.language || "en").toLowerCase();
  const subject =
    lang === "fr" ? "Vérifiez votre e-mail" :
    lang === "es" ? "Verifica tu correo" :
    lang === "pt" ? "Verifique seu e-mail" :
    lang === "ar" ? "تحقق من بريدك الإلكتروني" :
    lang === "hi" ? "अपने ईमेल की पुष्टि करें" :
    "Verify your email";

  const html = `
    <div style="font-family:system-ui,Segoe UI,Roboto,Arial;line-height:1.4">
      <h2>${subject}</h2>
      <p>Click the button below to verify your email.</p>
      <p style="margin:24px 0">
        <a href="${link}" style="background:#2563eb;color:#fff;padding:10px 14px;border-radius:8px;text-decoration:none">
          Verify Email
        </a>
      </p>
      <p style="color:#6b7280;font-size:12px">If you did not request this, you can ignore this email.</p>
    </div>
  `;

  if (!process.env.RESEND_API_KEY) {
    console.warn("RESEND_API_KEY missing; cannot send verification email.");
    return false;
  }

  try {
    const resp = await resend.emails.send({ from, to: email, subject, html });
    return !!resp?.data?.id;
  } catch (e) {
    console.error("Resend send failed:", e);
    return false;
  }
}
```

**Audit requirement**

* [ ] Agent ensures language is pulled from `users.language` when calling send.

### 9.2 Bootstrapping (client)

Create `client/src/i18n.ts`:

```ts
import i18n from "i18next";
import { initReactI18next } from "react-i18next";
import LanguageDetector from "i18next-browser-languagedetector";

import en from "./locales/en.json";
import fr from "./locales/fr.json";
import es from "./locales/es.json";
import pt from "./locales/pt.json";
import ar from "./locales/ar.json";
import hi from "./locales/hi.json";

export const SUPPORTED_LANGS = ["en","fr","es","pt","ar","hi"] as const;

i18n
  .use(LanguageDetector)
  .use(initReactI18next)
  .init({
    resources: {
      en: { translation: en },
      fr: { translation: fr },
      es: { translation: es },
      pt: { translation: pt },
      ar: { translation: ar },
      hi: { translation: hi },
    },
    fallbackLng: "en",
    supportedLngs: SUPPORTED_LANGS as unknown as string[],
    interpolation: { escapeValue: false },
    detection: {
      // Prefer server/user profile setting (store in localStorage on login)
      order: ["localStorage", "navigator"],
      caches: ["localStorage"],
    },
  });

export default i18n;
```
