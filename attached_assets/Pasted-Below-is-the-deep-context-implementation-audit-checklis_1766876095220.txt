# A) Scope Summary (What “complete” means)

The platform must provide:

1. **Signup flow** driven by the user’s **Country selection** that simultaneously triggers:

   * **Phone Validation Engine** (prefix, formatting, strict validation, E.164 storage)
   * **Legal Terms Assembly Engine** (Global Master + jurisdiction addendum via Country → Region → ROW fallback)

2. **Tamper-evident Legal Acceptance capture** at signup:

   * Stores the **exact combined text** presented + its **SHA-256 hash**
   * Stores provenance metadata: timestamp, country/region, user agent, IP, session id (where available)
   * Supports later verification (recompute SHA, diff vs current active terms)

3. **Admin “System Config” legal tooling**:

   * **Legal Docs**: manage versions per target; mark one version as “ACTIVE” via explicit targets table
   * **Legal Acceptances**: search, open detail, resolve doc links, deep-link to exact doc versions, diff vs current active
   * **Legal Coverage**: coverage grid for targets + one-click “Set Active → Latest”
   * **Gate toggle**: backend-controlled switch to enforce onboarding only where coverage is OK

4. **Replaceability / upgradability**:

   * Admin can upload new versions and re-point “active” without code changes
   * Supports country/region additions over time

# E) SQL Verification Queries (SQLite)

Agent 3 should run these (or equivalent through drizzle):

```sql
-- Targets coverage
SELECT doc_set, doc_type, jurisdiction_type, jurisdiction_key, active_doc_id, updated_at
FROM legal_doc_targets
ORDER BY updated_at DESC;

-- Latest docs per target (sanity)
SELECT doc_set, doc_type, jurisdiction_type, jurisdiction_key, MAX(created_at) AS latest_created_at
FROM legal_documents
GROUP BY doc_set, doc_type, jurisdiction_type, jurisdiction_key;

-- Acceptance integrity sampling
SELECT id, user_id, email_at_acceptance, country_iso2, region_key, accepted_at,
       LENGTH(combined_text) AS combined_len, combined_sha256
FROM legal_acceptances
ORDER BY accepted_at DESC
LIMIT 25;
```

* Resolver uses “latest created” even when targets exist (non-deterministic)

* Deep link doesn’t actually switch minitabs (listener missing at AdminDashboard root)
