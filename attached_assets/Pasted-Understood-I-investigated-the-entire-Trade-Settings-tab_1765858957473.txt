## 4) What Still Needs To Be Wired into the Trading/Risk Engine (Remaining Work)

This is the most critical part: **the UI is now saving settings**, but the engine must enforce them.

### A) riskMiddleware (server/risk.ts) must stop using hardcoded values

Right now `server/risk.ts` still hardcodes:

* Max 5 trades
* Max 3 per instrument
* Daily 10%
* Lifetime 20%

It must instead:

1. Load global settings (global_settings.id=1)
2. Apply these values dynamically:

   * `maxTradesPerUser`
   * `maxTradesPerInstrument`
   * `maxConcurrentLots`
   * `enableLossLimits`
   * `dailyLossLimitPercent`
   * `lifetimeLossLimitPercent`
3. Enforce the new “Maximum Concurrent Lots Per User” guardrail:

   * Sum lots across OPEN trades
   * If openLots + requestedLots > maxConcurrentLots → reject

This is the core “50 lots total concurrent exposure” requirement.

### B) orderEngine.ts must use global settings for pending fills

`server/engine/orderEngine.ts` currently checks:

* maxConcurrent from user settings OR fallback 5 ✅
* maxConcurrentLots from user settings OR fallback 50 ✅
* per instrument cap is **hardcoded 3** ❌ (must become global maxTradesPerInstrument)
* loss limits are NOT checked on pending fills ❌ (must enforce enableLossLimits + % limits before filling)

Otherwise pending orders become a bypass path.

### C) autoClose.ts must use Trade Settings tab values

`server/cron/autoClose.ts` is hardcoded:

* closes after 4 days
* runs every 60 minutes

But Trade Settings UI expects:

* enable/disable auto close
* configurable days
* configurable check frequency minutes

Implementation approach:

* Replace static `setInterval(60 min)` with a dynamic scheduling loop using `setTimeout`
* On each run, read global_settings:

  * if enableAutoClose false → do nothing, reschedule
  * use autoCloseAfterDays threshold
  * reschedule using autoCloseCheckFrequencyMinutes

### D) Market Hours must be enforced

Market hours tab must affect:

* Market order placement (`/api/trades`)
* Order engine executions if you want to block fills outside hours

Minimal enforcement recommended:

* If market is “closed” based on admin Market Hours:

  * block MARKET orders
  * allow pending orders to be placed, but only fill when market is open

To implement, define a reusable function:

* `isTradingAllowedNow(openTime, closeTime, allowWeekendTrading)`
  Then use it in:
* `/api/trades` for Market orders
* `orderEngine.ts` before filling triggered orders
* potentially `quoteService.ts` if you want “marketOpen” metadata accurate
