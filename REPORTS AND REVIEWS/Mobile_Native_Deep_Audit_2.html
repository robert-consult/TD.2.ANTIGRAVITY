Mobile Native Deep Audit 2

TradeQuip — TD.2.ANTIGRAVITY  |  Granular Code-Level Investigation  |  2026-03-10

✅ Update 2026-03-10: Findings #4, #7, #9, and #11 have been RESOLVED. 4 of 12 findings fixed.

Executive Summary

This second-pass audit inspects every source file in MOBILE/, NATIVE/, and all cross-repo bridge points in client/ and server/. 12 granular findings were identified: 3 critical security issues, 4 architectural warnings, and 5 informational items. 4 findings have since been resolved.

Critical Findings

🔴 #1 — Plaintext Signing Credentials in Repository

File: MOBILE/android/key.properties

Release keystore password (tradequip2026), key password, key alias, and the actual .keystore file are all tracked by Git in plaintext.

Impact: Complete signing identity compromise.

Fix: Add to .gitignore. Rotate keystore. Use CI secrets for release signing. (Deferred to end of development.)

🔴 #2 — Direct Cross-Subtree Import in MobileWrapperBridge

File: client/src/components/MobileWrapperBridge.tsx

import { ... } from "../../../MOBILE/src/mobile/utils";

Hard coupling between client/ and MOBILE/ via relative path.

Fix: Extract to shared/mobile-bridge/ workspace package.

🔴 #3 — NATIVE Dev Mode HTTP Breaks WebCrypto

File: NATIVE/src/services/runtimeConfig.ts

const DEV_APP_URL = Platform.OS === 'android'
    ? 'http://10.0.2.2:5000'
    : 'http://localhost:5000';

WebCrypto requires a secure context; HTTP dev URLs break auth on real devices.

Status: Rejected by gold-standard triage — current RN runtime model does not require WebCrypto for the native auth path. Re-evaluate only if a reproduced bug justifies it.

Resolved Findings

✅ #4 — Duplicate CSRF Fetch Logic — RESOLVED

Consolidated into MOBILE/src/mobile/utils/csrf.ts which imports CSRF_HEADER_NAME and CSRF_TOKEN_ENDPOINT from @shared/security/csrf. Both session-manager.ts and push-notifications.ts now import from ./csrf.

✅ #7 — No ProGuard on Release Builds — RESOLVED

MOBILE/android/app/build.gradle now has minifyEnabled true and shrinkResources true in the release build type. Debug builds remain unaffected.

✅ #9 — Incorrect Comment in useAuth — RESOLVED

Comment updated from "TradeQuip Android - Auth Hook" to "TradeQuip Native - Auth Hook" in NATIVE/src/hooks/useAuth.ts.

✅ #11 — Silent Push Disable Without Firebase Config — RESOLVED

MOBILE/android/app/build.gradle now emits a warning on release builds when google-services.json is missing, and hard-fails if TRADEQUIP_REQUIRE_GOOGLE_SERVICES_FOR_RELEASE=1 is set. Debug builds remain non-blocking.

Remaining Warnings

🟠 #5 — init-native.sh Outputs to Wrong Directory

File: NATIVE/init-native.sh

Creates ANDROID_NATIVE/ one level up, conflicting with the established NATIVE/ structure. Superseded by repo-local bootstrap fix already in place.

🟠 #6 — Missing iOS Deep Link / Universal Link Configuration

Neither MOBILE/ios/ nor NATIVE/ios/ contains:

  • Associated Domains entitlement
  • URL scheme registration for tradequip:// in Info.plist
  • apple-app-site-association hosting reference

Android deep linking is configured; iOS deep linking will silently fail.

Remaining Informational

🔵 #8 — WebSocket Singleton Initialized at Module Load

NATIVE/src/services/websocket.ts resolves the WS URL at import time. Dynamic config or environment switching would require a restart.

🔵 #10 — Minimal Push Notification Tests

NATIVE/__tests__/pushNotifications.test.ts is only 934 bytes. The complex push lifecycle deserves more coverage.

🔵 #12 — Dead env() Calls in Safe Area Utility

MOBILE/src/mobile/utils/mobile-utils.ts — getPropertyValue("env(...)") is always empty. Optional cleanup; the helper is currently unused.
