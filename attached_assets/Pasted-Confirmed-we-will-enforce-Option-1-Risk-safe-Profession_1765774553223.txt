What has been implemented (Option 1 enforcement)
1) MTM / Margin Engine: “Freeze on stale” (no fallback to openPrice)
File: server/recalcAccount.ts

Behavior now:

If the user has open positions, the engine requires fresh quotes.

If any required quote is missing or stale, recalcAccount() returns:

pricingStale: true

staleSymbols: [...]

and does NOT write new equity/freeMargin/usedMargin to users.

This removes the “dangerous mask” behavior where missing quotes were silently replaced by openPrice, which falsely forces:

floating P/L → 0

equity == balance
and hides feed failures.

Also added strict dependency on FX reference pairs (EURUSD, GBPUSD, USDJPY, USDCAD) for conversion correctness. If these are stale, MTM is considered stale.

2) Account Summary now explicitly reports stale status
File: server/routes.ts → /api/account/summary

The response now includes:

pricingStale

staleSymbols

asOf

So the frontend can display “pricing stale” and you have a proper audit signal instead of silent corruption.

3) Execution engine blocks trading & closing on stale quotes
File: server/routes.ts
A) /api/trades (opening a trade)

After fetching /api/quotes/latest, the engine now checks:

quote.isStale === true → returns HTTP 503 and refuses to open.

Additionally, after calling recalcAccount() (for margin check), it now blocks if:

metrics.pricingStale === true → refuses the order (prevents stale freeMargin use).

B) /api/trades/:id/close (closing a trade)

Same stale check:

quote.isStale === true → returns HTTP 503 and refuses to close.

This prevents the platform from closing trades using cached/ghost prices.

4) Auto-close job no longer uses fake/random prices
File: server/cron/autoClose.ts

Previously it used a simulated random market price, which is absolutely capable of generating “impossible closes” and unrealistic profits.

Now it:

pulls from the quotes table

refuses to auto-close if quote is stale/missing (consistent with Option 1)

closes using correct side logic (BUY closes on bid, SELL closes on ask)

This is a major risk-control correction.

5) A serious exploit was closed: user-supplied closePrice
File: server/routes.ts → /api/trades/:id/close

The endpoint previously allowed:

req.body.closePrice
Meaning a client could submit any close price and fabricate profits.

Now:

non-admins cannot supply closePrice

request is rejected if attempted

That is required for any “professional platform” posture.

Minimal UI support for “mark stale”

client/src/pages/AccountScreen.tsx
