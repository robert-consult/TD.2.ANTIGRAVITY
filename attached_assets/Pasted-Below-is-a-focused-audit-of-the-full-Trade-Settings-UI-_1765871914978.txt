Below is a focused audit of the full “Trade Settings UI → API → DB → enforcement” path, the gaps I found that could prevent changes from persisting/taking effect reliably, and the concrete code changes to harden persistence and ensure updated defaults are actually applied across the system.

---

## 1) End-to-end audit: does Trade Settings UI persist and apply changes?

### ✅ UI → API

* **AdminDashboard.tsx** posts Trade Settings to:

  * `PUT /api/admin/global-settings` (global defaults)
  * `PUT /api/admin/users/:id/settings` (per-user overrides)
* The UI already **invalidates and refetches** the `globalSettings` query after save, which is correct.

### ✅ API → DB

* Global settings are stored in **`global_settings`** (single row, typically `id=1`).
* Per-user settings are stored in **`user_settings`**.

### ✅ DB → Enforcement

The runtime enforcement happens in two key places:

* `server/risk.ts` middleware (**primary enforcement**)
* `server/routes.ts` trade placement handler (contains extra lot enforcement)

Both read from DB at request-time (no in-memory cache), so **once the DB is updated, changes take effect immediately** for new trade requests.

---

## 2) Problems found (these can break persistence / cause confusing defaults)

### Issue A — Inconsistent “defaults” across schema / API / enforcement

I found multiple conflicting defaults:

* `shared/schema.ts` had:

  * `maxTradesPerUser` default **10**
  * `maxTradesPerInstrument` default **5**
* But your intended behavior (and the rest of your enforcement logic) is:

  * **5 total concurrent trades**
  * **3 per instrument**
* Also, `server/engine/orderEngine.ts` used fallback **10**, which can diverge from risk middleware defaults.

**Impact:** Fresh installs or missing-row scenarios can “snap back” to different values than you set/expect.

---

### Issue B — `GET /api/admin/global-settings` did not guarantee a persisted row

If the table exists but has no row, the GET route returned an in-memory default **without inserting it**.

**Impact:** You could “see defaults” in UI, but nothing is actually persisted, and enforcement may behave differently until an explicit PUT happens.

---

### Issue C — PUT parsing used `Number(x) || default`

This pattern silently breaks legitimate values and can “undo” updates:

* `Number(0) || 50` becomes `50`
* string booleans like `"false"` become truthy via `Boolean("false") === true`

**Impact:** Admin changes can appear saved, but normalize incorrectly and lead to unexpected enforcement.

---

## 3) Fixes implemented (to ensure persistence + immediate effect)

### ✅ Fix 1 — Normalize defaults everywhere to 5 / 3

* `shared/schema.ts`
* Admin UI initial state
* Order engine fallback
* Risk middleware default response for market hours/weekend behavior

### ✅ Fix 2 — Ensure GET creates a durable global settings row

If missing, insert a default row (`id=1`) and return it.

### ✅ Fix 3 — Harden PUT parsing

* Proper numeric parsing (`undefined` if invalid)
* Proper boolean parsing for `"true"/"false"` strings
* Validate `HH:MM` format and bounds

### 2) PUT `/api/admin/global-settings` with safe parsing (no `||` fallbacks)

```diff
 app.put("/api/admin/global-settings", requireAdmin, async (req, res) => {
   try {
+    const parseNum = (v: any): number | undefined => {
+      if (v === null || v === undefined || v === "") return undefined;
+      const n = typeof v === "number" ? v : Number(v);
+      return Number.isFinite(n) ? n : undefined;
+    };
+
+    const parseBool = (v: any): boolean | undefined => {
+      if (v === null || v === undefined) return undefined;
+      if (typeof v === "boolean") return v;
+      if (typeof v === "string") {
+        const s = v.trim().toLowerCase();
+        if (s === "true") return true;
+        if (s === "false") return false;
+      }
+      return undefined;
+    };
+
+    const parseTime = (v: any): string | undefined => {
+      if (v === null || v === undefined || v === "") return undefined;
+      const s = String(v).trim();
+      const m = /^(\d{2}):(\d{2})$/.exec(s);
+      if (!m) return undefined;
+      const hh = Number(m[1]);
+      const mm = Number(m[2]);
+      if (hh < 0 || hh > 23 || mm < 0 || mm > 59) return undefined;
+      return `${m[1]}:${m[2]}`;
+    };
+
+    const body = req.body ?? {};
+
+    const next = {
+      defaultLeverage: parseNum(body.defaultLeverage),
+      maxPositionSize: parseNum(body.maxPositionSize),
+      maxTradesPerUser: parseNum(body.maxTradesPerUser),
+      maxTradesPerInstrument: parseNum(body.maxTradesPerInstrument),
+      maxConcurrentLots: parseNum(body.maxConcurrentLots),

+      marketCloseTime: parseTime(body.marketCloseTime),

+

       where: eq(globalSettings.id, 1),
     });

     if (existing) {
       await db.update(globalSettings)
         .set({
-          defaultLeverage: defaultLeverage !== undefined ? Number(defaultLeverage) : existing.defaultLeverage,
```
