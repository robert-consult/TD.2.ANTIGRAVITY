# A) MT5 / Professional Logic — Limit & Stop Orders (Reference Standard)

## 1) MT5-style trigger conditions (must be bid/ask-aware)

Use **Ask** for BUY triggers and fills; **Bid** for SELL triggers and fills.

### LIMIT orders

* **BUY LIMIT**: triggers when **ASK ≤ limitPrice**
* **SELL LIMIT**: triggers when **BID ≥ limitPrice**

### STOP orders

* **BUY STOP**: triggers when **ASK ≥ stopPrice**
* **SELL STOP**: triggers when **BID ≤ stopPrice**

This is critical: you cannot use “mid price” for triggers or fills and still claim MT5-like behavior.

---

## 2) MT5-style validation at placement (“wrong side” rejection)

These must be enforced at order placement:

### LIMIT placement rules

* **BUY LIMIT** must be **below current ASK**
* **SELL LIMIT** must be **above current BID**

### STOP placement rules

* **BUY STOP** must be **above current ASK**
* **SELL STOP** must be **below current BID**

If user tries to place a BUY LIMIT above ASK, MT5 would treat it as either invalid or “marketable”—in your platform, it must be rejected as invalid (unless you deliberately auto-convert to market, which I do not recommend for risk correctness).

---

## 3) Minimum distance requirement (“10 points from market”)

You asked for **10 points**.

Professional platforms implement this as a broker **StopLevel / FreezeLevel** rule. Your system currently has no such validation.

So you need:

* A computed **point size** per symbol (FX: pip/point logic; CFDs: tick size).
* Enforce: entry price must be at least **10 points away** in the correct direction.

Examples:

* BUY LIMIT: `limitPrice ≤ ASK - 10*point`
* SELL STOP: `stopPrice ≤ BID - 10*point`, etc.

---

## 4) SL/TP correctness rules (also MT5-aligned)

When SL/TP is set (at placement or after):

* BUY:

  * SL must be **below entry**
  * TP must be **above entry**
* SELL:

  * SL must be **above entry**
  * TP must be **below entry**
    Optionally also enforce min distance (10 points).

# B) Current Implementation Critique (What’s broken vs. MT5)

## 1) There is **no pending execution engine**

In the code you uploaded:

* `/api/trades` sets `status = PENDING` for Limit/Stop (via `storage.createTrade`)
* BUT there is **no backend process** that:

  * checks quotes,
  * triggers pending orders,
  * flips `PENDING → OPEN`,
  * sets `executedAt` and real `openPrice`.

Result:

* Limit/Stop orders are effectively “dead records” that never fill.

This is **not professional platform behavior**.

---

## 2) Order placement logic is not MT5-correct (server-side)

### File: `server/routes.ts` → `POST /api/trades`

Your server:

* fetches a quote
* calculates `entryPrice = ask for BUY / bid for SELL`
* writes that into `openPrice` **even for Limit/Stop**

That defeats the meaning of pending orders and creates incorrect “openPrice semantics.”

For pending orders:

* `openPrice` should represent **requested price** OR be nullable until execution (best practice is nullable openPrice + separate requested price fields).
* Actual entry should be set at execution time using bid/ask.

---

## 3) UI logic is not MT5-like for Limit/Stop

### File: `client/src/pages/TradeScreen.tsx`

Your UI:

* Always shows the same **BUY / SELL submit buttons**

* LimitPrice and StopPrice inputs are just generic fields with a placeholder = current price, not MT5-style suggested pricing.

You specifically requested:

* Limit/Stop mini-tabs should be **“Place Order: BUY LIMIT @ price”** etc.

That is not currently implemented.

---

## 4) “10 points suggestion” + “tracks market” is not implemented

Your current placeholders for TP/SL are ±1% from current price (not 10 points) and do not track in a disciplined “MT5-style pending order UI” way.

You want:
