### **1. The Signup Security: Sliding Captcha Integration**

To replace standard text captchas, we implement a "Slide to Verify" mechanism. This validates human interaction and is a prerequisite for the "Sign Up" button to become active.

* **Logic:** The `handleSubmit` function remains disabled until the `captchaVerified` state is `true`.
* **Replit Guidance:** Use a library like `react-slider-captcha` or a custom CSS/JS slider. The backend must receive a unique session token generated only upon a successful slide completion to prevent bot-spoofing the API request.

### **2. The Implementation Algorithm (The "Caveat Function")**

This algorithm handles the cascading logic triggered by the **Country Selector**.

#### **Step 1: Selection Trigger**

When the user selects a Country (e.g., "Poland"), the frontend triggers two parallel engines: `PhoneEngine` and `LegalEngine`.

#### **Step 2: Phone Prefix & Regex Engine**

1. **Lookup:** Match the ISO country code against the phone metadata.
2. **UI Update:** * Populate the prefix (e.g., `+48` for Poland).
* Apply the length/format regex to the input field.
* *Example:* If Kenya is selected, the field length is set to 9-10 digits and the prefix to `+254`.



#### **Step 3: Legal Terms Assembly (The Core Logic)**

The system resolves the document using a **Priority Fallback Chain**:

1. **Exact Match:** Does the `AddendumMap` have a specific file for "Poland"? If yes, load `DOC1_GLOBAL` + `ADD_POLAND`.
2. **Regional Resolution:** If no exact match, look up the "Region" for Poland.
* *Note:* Per your instructions, **Europe** is added as a region. If Poland resolves to `EUROPE`, it loads `DOC1_GLOBAL` + `ADD_EUROPE`.


3. **Default (ROW):** If the country/region is not found, load `DOC1_GLOBAL` + `ADD_ROW`.
