## Issues & Fixes

### 1) DOC1 re-accept upsert fails in Postgres
- Symptom: `/api/legal/doc1/reaccept` and any trade route running the DOC1 gate can 500 with `LEGAL_REACCEPT_*_FAILED`.
- Root cause: `legal_reaccept_requirements` lacks a unique constraint on `(user_id, doc_set)` but code uses `ON CONFLICT (user_id, doc_set)`.
- Fix plan:
  - Add Postgres migration to de-duplicate rows and create a unique index on `(user_id, doc_set)`.
  - Update Drizzle schema to declare the same unique index.
  - Verify: hit `/api/legal/doc1/reaccept` and trade gate path no longer errors.
 - Status: ✅ Fixed (migration `db/migrations/0006_legal_reaccept_requirements_unique.sql`, schema `shared/schema.pg.ts`)

### 2) Role-based task isolation bypassed by side-effect imports
- Symptom: quote polling + auto-close scheduling can start on any node that loads admin routes.
- Root cause: `server/feeds/quoteFeed.ts` and `server/cron/autoClose.ts` self-start on import, and admin routes import them.
- Fix plan:
  - Remove auto-start side effects; expose explicit `start*()` functions with idempotency.
  - Start tasks only from `server/index.ts` role-gated init.
  - Propagate “reload/reschedule” via `liveBus` events so admin changes apply across multi-role deployments.
  - Verify: importing admin routes does not start background loops; ingestor nodes still run them.
 - Status: ✅ Fixed (`server/feeds/quoteFeed.ts`, `server/cron/autoClose.ts`, `server/index.ts`, `server/routes/admin.ts`)

### 2b) Postgres ip2asn import can block startup (delays feed/cron)
- Symptom: server can appear “up” but ingestion/cron doesn’t start for a long time while ip2asn TSV is imported.
- Root cause: startup awaited a potentially long `maybeImportIp2AsnDataset()` job before starting feed/cron.
- Fix:
  - Run the import in the background so deferred init continues immediately.
 - Status: ✅ Fixed (`server/index.ts`)

### 3) `db:seed` fails without exported env
- Symptom: `npm run db:seed` can throw `DATABASE_URL is required for Postgres.`
- Root cause: script doesn’t load `.env`.
- Fix plan:
  - Run seed under `dotenv -e .env -- ...`.
  - Verify: `npm run db:seed` works from a clean shell.
 - Status: ✅ Fixed (`package.json`)

### 4) `db:audit` / `db:schema:dump` do not reflect Postgres reality
- Symptom: `db:audit` reports “OK” while not actually comparing code schema to the active Postgres DB.
- Root cause: scripts were legacy-db oriented and imported the wrong schema module for the selected dialect.
- Fix plan:
  - Make scripts dialect-aware; for Postgres compare Drizzle PG schema → `information_schema` columns.
  - Keep legacy paths only as optional.
  - Verify: `npm run db:audit` flags real mismatches (and passes when aligned).
 - Status: ✅ Fixed (`scripts/dbAudit.ts`, `scripts/dbDumpSchema.ts`, `package.json`)

### 5) Drizzle config must be Postgres-only
- Symptom: migrations/tooling could drift if Drizzle is configured with multiple dialect branches.
- Fix plan:
  - Make `drizzle.config.ts` Postgres-only (`schema.pg.ts`, `dialect: postgresql`).
 - Status: ✅ Fixed (`drizzle.config.ts`)

### 7) Swahili (sw) UI shows mixed languages (e.g., Swedish/Albanian)
- Symptom: Selecting Swahili results in mixed-language UI strings (Swahili + Swedish/other), e.g. `Save Settings` shows as Swedish `Spara Inställningar`.
- Root cause: Bad data in Postgres: `i18n_translations.locale='sw'` contained Swedish/Albanian/wrong-language strings generated by the LLM (historically the short locale code `sw` was misinterpreted).
- Fix:
  - Hardened OpenAI translation prompting for `sw` (explicit Swahili/Kiswahili ≠ Swedish/Svenska), reduced batch size, preserved placeholders, and added retry + worker-side validation to prevent storing non-Swahili output.
  - Repaired the DB by re-queuing/deleting the suspect `sw` rows and re-running the i18n worker.
  - Verified via DB queries:
    - `SELECT COUNT(*) FROM i18n_translations WHERE locale='sw' AND translated_text ~ '[åäöÅÄÖ]';` → `0`
    - `SELECT COUNT(*) FROM i18n_translations WHERE locale='sw' AND translated_text ILIKE '%Handel%';` → `0`
    - `SELECT COUNT(*) FROM i18n_translations WHERE locale='sw' AND translated_text ILIKE '%Ekzekutuar%';` → `0`
    - `SELECT COUNT(*) FROM i18n_translations WHERE locale='sw' AND translated_text ~ '[àáâãäåæçèéêëìíîïñòóôõöøùúûüýÿ]';` → `0`
- Status: ✅ Fixed (`server/i18n/providers/openai.ts`, `server/i18n/worker.ts`, `scripts/i18nRepairLocale.ts`)
